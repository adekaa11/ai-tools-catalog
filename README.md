# Catalyst — персональный каталог ИИ-инструментов

**Catalyst** — одностраничное React-приложение для личного учёта AI-сервисов, полезных ссылок, реферальных программ и API endpoints. Оно работает полностью в браузере: сервер, база данных и ключи окружения для базового сценария не требуются.

> Данные сохраняются в `localStorage` текущего браузера. Это упрощает локальный запуск, но означает, что данные не синхронизируются между браузерами и устройствами.

## Возможности

| Функция | Описание |
| --- | --- |
| **CRUD каталога** | Добавление, редактирование и удаление карточек инструментов через модальное окно. |
| **Поиск** | Фильтрация по названию, описанию, категории и тегам. |
| **Категории** | Разделы для генерации кода, текста, изображений, API-провайдеров и продуктивности. |
| **Теги** | Множественные теги с добавлением по Enter или запятой. |
| **Быстрое копирование** | Копирование API endpoint и реферальной ссылки из карточки. |
| **Тёмная тема** | Переключается вручную и запоминается между сессиями браузера. |
| **Адаптивность** | Интерфейс рассчитан на десктоп и мобильные устройства; на телефоне категории доступны через селектор. |

## Быстрый старт

### Требования

Для запуска потребуются актуальная LTS-версия Node.js и менеджер пакетов `pnpm`. Приложение также можно открыть и дорабатывать в VS Code.

### Установка и запуск

Откройте терминал в корневой папке проекта и выполните следующие команды:

```bash
pnpm install
pnpm dev
```

После запуска Vite выведет локальный адрес, обычно `http://localhost:3000`. Откройте его в браузере.

### Проверка перед коммитом

Следующие команды выполняют проверку типов и production-сборку:

```bash
pnpm check
pnpm build
```

| Команда | Назначение |
| --- | --- |
| `pnpm dev` | Запускает Vite dev server с hot reload. |
| `pnpm check` | Запускает TypeScript без генерации файлов. |
| `pnpm build` | Создаёт production-сборку в `dist/`. |
| `pnpm start` | Запускает собранную production-версию. |
| `pnpm format` | Форматирует исходники через Prettier. |

## Модель данных

Каждая карточка хранится как объект `ToolEntry`. Поля `id` и `createdAt` формируются автоматически в момент добавления.

```ts
type ToolEntry = {
  id: string;
  name: string;
  description: string;
  websiteUrl: string;
  referralUrl: string;
  apiUrl: string;
  category: ToolCategory;
  tags: string[];
  createdAt: string;
};
```

Категории определены централизованно в `client/src/types/tool.ts`:

| Значение | Назначение |
| --- | --- |
| `Генерация кода` | IDE-ассистенты, агентные среды, генераторы кода. |
| `Текст` | Чат-боты, редакторы и инструменты для работы с контентом. |
| `Изображения` | Генерация, редактирование и обработка визуальных материалов. |
| `API-провайдеры` | Модели, inference API и инфраструктурные сервисы. |
| `Продуктивность` | Автоматизация, заметки, планирование и личные рабочие процессы. |

## Работа с локальным хранилищем

Карточки сериализуются в JSON под ключом `catalyst-ai-tools-v1`. Выбор темы сохраняется под ключом `catalyst-theme`.

Чтобы очистить только каталог в DevTools Console, выполните:

```js
localStorage.removeItem("catalyst-ai-tools-v1");
```

Чтобы очистить каталог и выбранную тему, выполните:

```js
localStorage.removeItem("catalyst-ai-tools-v1");
localStorage.removeItem("catalyst-theme");
```

После очистки перезагрузите страницу. Для реального пользователя достаточно очистить данные сайта через настройки браузера.

## Дальнейшая доработка

### Добавление новой категории

Откройте `client/src/types/tool.ts` и добавьте значение в массив `CATEGORIES`. Затем добавьте описание визуального состояния в объект `CATEGORY_META`. Так новая категория автоматически появится в форме, сайдбаре и мобильном фильтре.

### Миграция на серверное хранение

Текущая логика хранения изолирована в `client/src/lib/toolStorage.ts`. Для перехода на SQLite, PostgreSQL или другой backend замените функции `loadTools` и `saveTools` запросами к API и перенесите CRUD-операции из `Home.tsx` в отдельный сервис или data-hook. Тип `ToolEntry` можно сохранить как контракт между frontend и backend.

### Экспорт и импорт

Локальные записи уже имеют JSON-представление. Для резервного копирования можно добавить две кнопки: экспорт `tools` через `Blob` и импорт через `<input type="file">` с проверкой структуры данных. Это естественное расширение для сценария `localStorage`.

### Добавление тестов

Проект содержит Vitest в зависимостях. Практичный следующий шаг — покрыть тестами `toolStorage.ts`, поиск/фильтрацию и преобразование тегов в `ToolDialog.tsx`.

## Дизайн-система

Приложение следует концепции **«Каталожная мастерская»**. Боковая панель играет роль корешка картотеки: она использует индексные номера и вертикальную ось. Карточки передают метафору бумажных индексов через табы категорий, штампы и тонкую маркировку. Фирменный цвет **Catalyst Vermilion** (`#E9532D`) зарезервирован для действий, активного состояния и маленькой брендовой точки-ядра.

Подробные решения по визуальному языку находятся в [`ideas.md`](./ideas.md).

## Окружение

Для локального режима отдельный файл `.env` не требуется. Шаблон включает служебные переменные аналитики для рабочей среды, но основной функционал каталога не зависит от внешних API, секретов или базы данных.

## Ограничения текущей версии

Поскольку данные сохраняются только в браузере, очистка данных сайта, переход в другой браузер или работа на другом устройстве не перенесут записи автоматически. Приложение также намеренно не содержит авторизацию и общий доступ к каталогу — эти возможности потребуют серверного слоя.
